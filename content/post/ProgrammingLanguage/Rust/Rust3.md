## 前言

所有权（Ownership）是 Rust 最独特的设计，也是很多人在学习 Rust 时遇到的第一道真正的门槛。理解它需要先理解一件事：内存。

## 栈与堆

程序运行时使用的内存分为两个主要区域：栈（Stack）和堆（Heap）。

**栈**是后进先出的结构，操作系统自动管理。函数被调用时，在栈上为它的局部变量分配一块空间；函数返回时，这块空间被自动回收。栈上的数据必须在**编译期已知大小**，操作极快，分配和释放几乎是瞬间完成的（只是移动一个指针）。整数、浮点数、布尔值、固定长度的数组——这些类型存在栈上。

**堆**更灵活，可以在运行时动态分配任意大小的内存。但代价是：程序需要向操作系统申请内存（分配），用完后归还（释放），这两步都有开销，而且如果管理不当，要么内存泄漏（只申请不归还），要么重复释放（同一块内存归还两次，导致崩溃）。`String`、`Vec<T>` 这类大小在运行时才确定的类型，数据存在堆上。

主流语言处理堆内存的方式有三种：C/C++ 让程序员自己管理（`malloc/free`，最高效但容易出错）；Java/Python/Go 用垃圾回收器在运行时自动追踪（安全省心，但有运行时开销和 GC 暂停）；Rust 的所有权系统在**编译期**完成分析，生成和手写代码等效的分配/释放指令，零运行时开销，同时保证安全。

## 所有权的三条规则

Rust 的所有权系统建立在三条规则上：

- Rust 中每个值都有一个**所有者（owner）**
- 任意时刻，一个值有且只有**一个所有者**
- 所有者**离开作用域**时，这个值被**自动丢弃（drop）**

```rust
fn main() {
    {
        let s = String::from("hello"); // s 是这块字符串数据的所有者
        println!("{}", s);             // 可以使用 s
    }                                  // s 的作用域结束，Rust 自动调用 drop，释放堆内存

    // println!("{}", s); // 这里 s 已经不存在了，编译报错
}
```

`drop` 是一个特殊函数，类似 C++ 的析构函数。Rust 编译器会在每个值的作用域末尾自动插入对应的 `drop` 调用，程序员不需要手动写。这套机制叫 RAII（资源获取即初始化），保证了资源（内存、文件句柄、网络连接等）不会泄漏。

## 移动（Move）

把一个 `String` 赋值给另一个变量时，会发生什么？

`String` 在栈上存的是三个字段：指向堆上字符数据的指针、字符串的长度、分配的容量。赋值时，这三个字段被复制到新变量——也就是说，两个变量的指针指向同一块堆内存。

如果 Rust 允许这样做，那么两个变量离开作用域时，`drop` 会被调用两次，同一块堆内存被释放两次，这就是 **double free**——C++ 里恶名昭著的内存错误之一。

Rust 的解法是：赋值后，**原来的变量立刻失效**，所有权转移到新变量。这叫**移动（Move）**：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 的所有权移动到 s2，s1 失效

    // println!("{}", s1); // 编译错误：value borrowed here after move
    println!("{}", s2); // 正常
}
```

和 Python 不同，Python 的赋值是让两个变量指向同一个对象，两者都有效。Rust 的移动是转移唯一所有权，原变量不能再用。

### Copy：基本类型的例外

对于存在栈上的基本类型，赋值时会直接**按位复制**，原变量仍然有效：

```rust
fn main() {
    let x = 5;
    let y = x; // i32 被复制，x 和 y 各自独立
    println!("{} {}", x, y); // 两者都有效
}
```

实现了 `Copy` trait 的类型赋值时复制而不是移动。常见的 Copy 类型包括：所有整数类型、浮点类型、`bool`、`char`、以及元素类型都是 Copy 的数组和元组。

判断规则很简单：完全存在栈上的类型可以 Copy，涉及堆内存的不行。`String` 管理着堆上的数据，不能 Copy；`i32` 只在栈上，可以 Copy。

## 克隆（Clone）

如果真的需要 `String` 的独立副本，用 `.clone()`：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // 堆上的数据也被完整复制了一份

    println!("{} {}", s1, s2); // 两者都有效，各自独立
}
```

`.clone()` 会在堆上申请新的内存，把字符数据复制过去，代价比移动高得多。Rust 要求显式写出 `.clone()`，就是在提醒你这里有额外开销。

## 函数与所有权

所有权的转移在函数调用时同样发生，把值传给函数和把值赋给变量，所有权行为完全相同：

```rust
fn consume(s: String) {
    println!("{}", s);
}   // s 离开作用域，drop 被调用，堆内存释放

fn main() {
    let s = String::from("hello");
    consume(s);              // s 的所有权移入函数

    // println!("{}", s);   // 编译错误：s 已被移走
}
```

如果你想在函数调用后继续使用这个值，可以把所有权再从函数里返回出来，但这样写很繁琐。Rust 提供了一个更优雅的方案：引用。

## 引用与借用

引用允许你使用一个值而不取走它的所有权，这叫**借用（Borrowing）**。在类型前加 `&` 表示引用。

通用语法格式：

```text
// 创建引用（借用一个值）
let 引用变量 = &变量;           // 不可变引用，类型是 &T
let 引用变量 = &mut 变量;       // 可变引用，类型是 &mut T（原变量必须声明为 mut）

// 函数参数中使用引用
fn 函数名(参数: &类型) -> 返回类型 { ... }      // 接受不可变引用
fn 函数名(参数: &mut 类型) -> 返回类型 { ... } // 接受可变引用

// 调用时传入引用
函数名(&变量);       // 传不可变引用
函数名(&mut 变量);   // 传可变引用（原变量必须是 mut）
```

```rust
fn length(s: &String) -> usize {
    s.len()
}   // s 是引用，不是所有者，所以这里 drop 不会释放数据

fn main() {
    let s = String::from("hello");
    let len = length(&s);           // 传入引用，s 的所有权不转移
    println!("'{}' 长度是 {}", s, len); // s 仍然有效
}
```

默认的引用是**不可变**的，通过引用不能修改数据。如果需要通过引用修改，用可变引用 `&mut`：

```rust
fn append(s: &mut String) {
    s.push_str(", sekai");
}

fn main() {
    let mut s = String::from("hello"); // 变量本身也必须是 mut
    append(&mut s);
    println!("{}", s); // hello, sekai
}
```

### 借用规则

Rust 对引用有严格的约束，只有两条，但必须同时满足：

第一条：可以有任意多个**不可变引用**同时存在。

第二条：**可变引用**同一时刻只能有一个，且不能与不可变引用共存。

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // 不可变引用 1
    let r2 = &s; // 不可变引用 2，没问题
    println!("{} {}", r1, r2);
    // r1 和 r2 的最后一次使用在这里，之后它们就"不存在"了

    let r3 = &mut s; // 可变引用，此时 r1 r2 已经不再使用，可以
    r3.push_str("!");
    println!("{}", r3);
}
```

引用的有效范围是从声明开始，到**最后一次使用**结束，不是到词法作用域结束。这个改进在 Rust 2018 Edition 引入，叫 Non-Lexical Lifetimes（NLL），让很多"在逻辑上安全"的代码不会被编译器拒绝。

这两条规则背后的道理：如果同时存在多个写入者，或者一边写一边读，就可能产生数据竞争（一个指针在读，另一个在写，且没有同步）。Rust 在编译期就把这种情况全部拦截了，不需要等到运行时。

### 悬垂引用

Rust 还会阻止你创建**悬垂引用**——指向已经释放的内存的引用：

```rust
fn dangle() -> &String {     // 试图返回局部变量的引用
    let s = String::from("hello");
    &s                        // s 在函数结束时被 drop，引用就悬空了
}                             // 编译错误：returns a reference to data owned by the current function
```

这在 C++ 里是合法的（只是未定义行为，实际会导致各种诡异问题），Rust 在编译期直接拒绝。解决方法是把值本身返回出去，而不是返回引用：

```rust
fn no_dangle() -> String {
    let s = String::from("hello");
    s // 把所有权返回给调用者，不会 drop
}
```

## 切片（Slice）

切片是对连续内存中某一段的**引用**，不拥有所有权。它本身是一个"胖指针"，包含两部分：指向数据起始位置的指针，以及这段数据的长度。

通用语法格式：

```text
// 字符串切片，类型是 &str
&字符串[起始字节..结束字节]  // 左闭右开 [start, end)，注意是字节位置而非字符数
&字符串[起始字节..=结束字节] // 左闭右闭 [start, end]
&字符串[..结束字节]          // 从开头到指定字节
&字符串[起始字节..]          // 从指定字节到末尾
&字符串[..]                  // 整个字符串

// 数组/Vec 切片，类型是 &[T]（T 是元素类型）
&数组[起始下标..结束下标]    // 按元素下标取一段，不是字节数
```

字符串切片的类型是 `&str`，语法是 `&s[起始..结束]`：

```rust
fn main() {
    let s = String::from("hello sekai");

    let hello = &s[0..5];  // 字节索引 [0, 5)，即 "hello"
    let sekai = &s[6..11]; // 即 "sekai"

    println!("{} {}", hello, sekai);

    // 简写形式
    let all  = &s[..];    // 整个字符串
    let head = &s[..5];   // 前 5 个字节
    let tail = &s[6..];   // 第 6 个字节到末尾
}
```

切片的起止索引指的是**字节位置**，不是字符数量。Rust 的字符串用 UTF-8 编码，英文字符 1 字节，汉字 3 字节，切割时必须保证切割点在字符边界上，否则运行时 panic：

```rust
fn main() {
    let s = String::from("你好");
    // let hello = &s[0..1]; // panic：不在字符边界上（"你"占 3 字节）
    let hello = &s[0..3];    // 正确，"你"
}
```

字符串字面量的类型就是 `&str`，它是对程序二进制数据段里字符串内容的引用，生命周期是整个程序运行期间（`'static`）：

```rust
fn main() {
    let s: &str = "hello sekai"; // 类型就是 &str
}
```

切片的用处之一是让函数可以同时接受 `String` 和 `&str`，不需要把数据复制一份：

```rust
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();
    for (i, &byte) in bytes.iter().enumerate() {
        if byte == b' ' {
            return &s[..i]; // 找到空格，返回空格前的部分
        }
    }
    &s[..] // 没有空格，整个字符串都是第一个词
}

fn main() {
    let s = String::from("hello sekai");
    let word = first_word(&s); // &String 可以自动转换为 &str

    // 如果在这里修改 s，编译器会报错，因为 word 还持有对 s 的不可变引用
    // s.clear(); // 编译错误

    println!("第一个词: {}", word);
}
```

这个例子展示了切片的一个重要价值：`first_word` 返回了对 `s` 的引用，只要 `word` 还在使用，借用检查器就不允许修改 `s`。这种在编译期防止"使用了已经失效的引用"的能力，是 Rust 区别于大多数语言的核心优势之一。

数组切片和字符串切片类似，类型是 `&[T]`：

```rust
fn main() {
    let arr = [1, 2, 3, 4, 5];
    let slice: &[i32] = &arr[1..4]; // [2, 3, 4]
    println!("{:?}", slice);
}
```
