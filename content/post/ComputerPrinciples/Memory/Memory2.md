## 前言

上一篇建立了内存的物理模型：内存是一个巨大的字节数组，每个字节有唯一的地址。那么地址本身能不能存在内存里、当成数据来传递和操作？可以，这就是**指针（Pointer）**——内存里最重要、也最容易误用的概念。

理解指针是理解所有内存相关问题的基础：C/C++ 的手动内存管理、Rust 的借用检查、操作系统的内核数据结构，本质上都在围绕"谁持有什么地址、这个地址是否有效"这个核心问题打转。

## 地址也是数据

### 指针的本质

指针是一个存放内存地址的变量。它和普通的 `int`、`double` 本质上没有区别，都占据一块内存；区别在于，我们把它里面的数值**解释为地址**，用来间接访问那个地址上的数据。

在 64 位系统上，一个指针占 **8 字节**，因为地址是 64 位整数。不管指针指向 `char`（1 字节）、`int`（4 字节）还是一个几 MB 的结构体，指针变量本身始终是 8 字节。

```text
内存示意（64 位系统）：

地址        内容
0x1000  [  0x00002008  ]  ← 指针 p，存放地址 0x2008，本身占 8 字节
0x1008  [  ......      ]

0x2008  [  42          ]  ← p 指向的 int，占 4 字节
0x200C  [  ......      ]
```

`p` 的值是 `0x2008`，这只是一个整数。当我们**解引用**（dereference）`p` 时，CPU 用这个整数作为地址，去读取 `0x2008` 处的内容。

## C 语言中的指针

### 声明、取地址与解引用

```c
int x = 42;
int *p = &x;   // &x 取 x 的地址，赋给指针 p（int*）
```

`int *p` 声明 `p` 是"指向 int 的指针"。`&x` 是**取地址运算符**，返回 `x` 在内存中的起始地址。

```c
int val = *p;  // *p 解引用：取 p 指向地址上的值，val = 42
*p = 100;      // 通过指针修改 x 的值，x 变为 100
```

`*` 在声明里是类型修饰符（"这是个指针类型"），在表达式里是解引用运算符（"取指针指向的值"）——同一个符号，两种含义，初学时容易混淆。

### 指针运算

对指针做加减运算时，步长不是字节，而是**所指类型的大小**：

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;   // p 指向 arr[0]，假设地址 0x1000

p + 1;         // 地址 0x1004（+ 1 个 int = + 4 字节）
p + 2;         // 地址 0x1008
*(p + 3);      // 40，等价于 arr[3]
```

数组下标本质上就是指针运算：`arr[i]` 在 C 里严格等价于 `*(arr + i)`。`arr` 在表达式中会"退化"为指向首元素的指针，这就是数组和指针在 C 里密不可分的原因。

### 通过指针修改参数

C 只有值传递。想在函数内修改调用方的变量，需要传指针：

```c
void swap(int *a, int *b) {
    int tmp = *a;
    *a = *b;
    *b = tmp;
}

int x = 3, y = 7;
swap(&x, &y);  // 传地址，函数内通过指针修改原值
// 现在 x == 7, y == 3
```

### void 指针

`void *` 是"不知道指向什么类型"的通用指针。`malloc` 返回 `void *`，调用方强转为所需类型：

```c
int *arr = (int *)malloc(10 * sizeof(int));
```

`void *` 不能直接解引用（不知道要读几个字节），也不能做指针运算（不知道步长），必须先强转为具体类型。

## 指针的危险

### 空指针（Null Pointer）

```c
int *p = NULL;
*p = 42;  // 空指针解引用！操作系统发送 SIGSEGV，程序崩溃
```

`NULL` 在大多数平台上是 0。操作系统故意不把任何内存映射到地址 0，所以访问 `NULL` 必然触发段错误——这是刻意设计的防护机制。

### 悬空指针（Dangling Pointer）

指向的内存已经被释放，但指针还在被使用：

```c
int *p = malloc(sizeof(int));
free(p);
*p = 42;  // 未定义行为！这块内存可能已被分配给别人
```

栈上也有同样的问题：

```c
int *dangerous() {
    int local = 42;
    return &local;  // 返回栈上局部变量的地址
}                   // 函数返回后栈帧消失，这个指针立刻成为悬空指针
```

### 野指针（Wild Pointer）

未初始化的指针，其值是内存里的随机数：

```c
int *p;   // 未初始化
*p = 42;  // 写入随机地址，可能破坏任何数据
```

好习惯：声明时立刻初始化（赋为 `NULL` 或合法地址），`free` 之后立刻置 `NULL`。

## C++ 的引用

C++ 在指针之上引入了**引用（Reference）**，语法更简洁，规则更严格。

### 引用是别名

引用是已有变量的另一个名字。不是独立的存储，就是原变量本身，底层通常实现为一个不可更改的指针：

```cpp
int x = 42;
int &ref = x;   // ref 是 x 的引用，绑定后不可更改指向

ref = 100;      // 修改 ref 等于修改 x
std::cout << x; // 输出 100

int *p = &ref;  // &ref 取的就是 x 的地址，p == &x
```

### 引用的三条限制

这三条规则让引用比裸指针更安全：

**必须初始化**，没有"空引用"：

```cpp
int &ref;        // 编译错误：引用必须在声明时绑定
```

**不能重新绑定**，一旦绑定就指向同一对象直到生命周期结束：

```cpp
int a = 1, b = 2;
int &ref = a;
ref = b;  // 这是把 b 的值赋给 a，不是让 ref 指向 b
```

**没有引用的引用**，也不能做指针运算。

### 引用参数 vs 指针参数

```cpp
// C++ 版 swap，用引用参数更清晰
void swap(int &a, int &b) {
    int tmp = a;
    a = b;
    b = tmp;
}

swap(x, y);  // 调用方不用写 &x，但函数内确实修改了原值
```

引用参数的"陷阱"是：从调用点看起来像值传递，但函数内可以修改参数。如果函数不打算修改参数，应该用 `const &` 明确表达意图。

## Rust 的引用与借用

Rust 的引用在语义上类似 C++ 引用，但有编译期强制执行的借用规则，从根源上消除悬空指针和数据竞争。

### &T 和 &mut T

```rust
let x = 42_i32;
let r = &x;         // 不可变引用：可以读，不能写
println!("{r}");    // 42

let mut y = 10_i32;
let rm = &mut y;    // 可变引用：可以读写
*rm = 100;
println!("{y}");    // 100
```

在底层，`&T` 和 `&mut T` 同样是 8 字节的地址，但编译器在编译期强制以下规则：

### 借用规则（Borrow Rules）

同一时刻，同一数据要么有**任意多个** `&T`（只读），**要么**有恰好**一个** `&mut T`（可写），二者不能同时存在。引用的生命周期也不能超过被引用的数据。

这两条规则在编译期静态检查，运行时零开销——既不像 C/C++ 那样什么都不检查，也不像 GC 语言那样在运行时付出代价。

```rust
let mut v = vec![1, 2, 3];

let r1 = &v;      // OK，不可变借用
let r2 = &v;      // OK，可以有多个不可变借用
// let rm = &mut v; // 编译错误：已有不可变借用，不能同时有可变借用

println!("{r1:?} {r2:?}"); // r1, r2 的借用在这里结束

let rm = &mut v;  // OK，此时 r1/r2 已过期
rm.push(4);
```

### 编译期拒绝悬空引用

```rust
fn dangling() -> &i32 {
    let x = 42;
    &x  // 编译错误：x 在函数结束时被丢弃，引用会悬空
}
```

Rust 编译器追踪每个引用和被引用数据的生命周期，一旦发现引用可能活得比数据更长，就在编译期报错。

### 生命周期注解

大多数情况下编译器能自动推断，不需要显式写。当函数接收和返回引用、编译器无法独自推断时，需要手动标注：

```rust
// 告诉编译器：返回值的生命周期与两个参数中较短的那个一样长
fn longest<'a>(s1: &'a str, s2: &'a str) -> &'a str {
    if s1.len() >= s2.len() { s1 } else { s2 }
}
```

### 智能指针简介

Rust 的"智能指针"在普通引用之上封装了额外的所有权语义：

`Box<T>` 独占所有权，堆上分配，作用域结束自动释放，等价于 C++ 的 `unique_ptr`。`Rc<T>` 引用计数，允许多个所有者共享数据（单线程）。`Arc<T>` 是线程安全版本的 `Rc`。而 `&T` / `&mut T` 只是借用，不持有所有权，不负责释放。

## 多级指针

指针本身也占内存，所以可以有"指向指针的指针"：

```c
int x = 42;
int  *p  = &x;   // p  → x
int **pp = &p;   // pp → p → x

**pp;       // 42，两次解引用到 x 的值
*pp = NULL; // 修改 p 的值（让 p 变成 NULL），不影响 x
```

多级指针在 C 里处理二维数组或需要在函数内修改指针本身时会用到。一般不超过两级，再多就难以阅读。

## 函数指针

指针也可以指向函数——存储函数的入口地址：

```c
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

// 函数指针类型：指向"接受两个 int，返回 int 的函数"
int (*op)(int, int);

op = add;
printf("%d\n", op(3, 4));  // 7

op = sub;
printf("%d\n", op(3, 4));  // -1
```

函数指针是 C 实现回调（callback）的基础，C++ 的虚函数在底层用 vtable（虚函数表，本质是函数指针数组）实现。

## 小结

指针是内存模型的延伸：

- 指针存放地址，在 64 位系统上始终占 8 字节，无论指向什么类型
- `*p` 解引用，从地址读取数据；`&x` 取地址，获得变量的地址
- 指针运算以所指类型大小为步长；`arr[i]` 严格等价于 `*(arr + i)`
- C++ 的引用是"不可重绑定、无法为空的指针别名"，语法更安全
- Rust 的借用系统在编译期消除悬空指针和数据竞争，代价是理解借用规则
- 函数指针存储函数入口地址，是回调和多态的基础
