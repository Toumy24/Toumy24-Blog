## 前言

写了那么久代码，你有没有想过：`int x = 5;` 这一行，那个 `5` 究竟存在哪里？它占了多少空间？CPU 是怎么找到它的？

这个系列从最底层开始讲内存——不是"分配一块内存"这种抽象层面，而是真正搞清楚内存是什么、怎么工作、为什么要这样设计。理解了这些，你看 Rust 的所有权、C 的指针、操作系统的虚拟内存，都会有一种"原来如此"的感觉。

## 内存的物理本质

### 从一个比特开始

计算机里最小的信息单位是**比特（bit）**，它只能存储两种状态：0 或 1。

在实际的 DRAM（动态随机存取存储器，也就是我们通常说的"内存条"）里，每一个比特对应一个**电容**——电容充电表示 1，放电表示 0。电容会缓慢漏电，所以 DRAM 需要周期性刷新（每隔几毫秒就重新充电），这也是它叫"动态"的原因。

相比之下，SRAM（静态随机存取存储器，用于 CPU 缓存）用的是触发器电路，不需要刷新，速度更快，但每个比特需要 4~6 个晶体管，成本和面积都更高。

```text
DRAM 单元（概念示意）：

  字线（Word Line）
       │
  ─────┤ 晶体管（开关）
       │
  ─────┴──[电容]───── 位线（Bit Line）
               │
              GND

字线高电平 → 晶体管导通 → 可读写电容上的电荷
```

### 字节：最小的可寻址单位

8 个比特组成 1 **字节（byte）**。内存以字节为单位编址——每个字节都有一个唯一的**内存地址（address）**，就像门牌号一样。

```text
地址 0x0000: [0][1][1][0][0][1][0][1]  ← 8 bits = 1 byte，值为 0x65 = 101
地址 0x0001: [0][0][1][0][0][0][0][1]  ← 值为 0x21 = 33
地址 0x0002: [0][0][0][0][0][0][0][0]  ← 值为 0x00 = 0
     ...
```

"以字节寻址"是现代计算机的通用设计。CPU 向内存发出一个地址，内存返回那个地址上的 1 个字节（或一次性返回多个连续字节）。

### 多字节数据的存储

`int`（4 字节）、`double`（8 字节）等类型需要占据多个连续字节。这里就产生了一个问题：多字节的数，高位字节放在低地址还是高地址？

这叫**字节序（Endianness）**，有两种：

**大端序（Big-Endian）**：高位字节在低地址，低位字节在高地址。读起来和人写数字的顺序一致。

**小端序（Little-Endian）**：低位字节在低地址，高位字节在高地址。

```text
以 32 位整数 0x12345678 为例，存放在地址 0x1000 起：

地址      大端序    小端序
0x1000     0x12      0x78
0x1001     0x34      0x56
0x1002     0x56      0x34
0x1003     0x78      0x12
```

x86/x86-64（也就是你的 PC 和大多数服务器）使用**小端序**。ARM 通常也默认小端序。网络协议（TCP/IP）规定用大端序传输，所以网络编程里经常要做字节序转换（`htonl`、`ntohl`）。

大多数时候你不需要关心字节序，但以下情况必须注意：
- 读写二进制文件（尤其是跨平台时）
- 网络通信
- 直接操作内存（类型转换、联合体等）

## 内存地址空间

### 什么是地址空间

**地址空间**是一组可用的内存地址的集合。在 32 位系统上，地址是 32 位的整数，地址空间大小是 $2^{32}$ = 4 GiB——也就是最多能寻址 4 GB 的内存。在 64 位系统上，地址是 64 位的，理论地址空间是 $2^{64}$ ≈ 16 EiB，实际上目前的 CPU 只用了低 48 位，够用很久了。

```text
32 位地址空间：

0x00000000 ─── 起始地址
0x00000001
0x00000002
    ...
0xFFFFFFFE
0xFFFFFFFF ─── 末尾地址（共 4,294,967,296 个字节 = 4 GiB）
```

### 物理地址 vs 逻辑地址

这里有个关键区分：

- **物理地址（Physical Address）**：内存条上真实的位置编号，由内存控制器直接使用。
- **逻辑地址 / 虚拟地址（Virtual Address）**：程序代码里使用的地址，由操作系统和 CPU 的 MMU（内存管理单元）负责翻译成物理地址。

这个虚拟地址的设计是操作系统最重要的机制之一，我们放到第 4 篇详细讲。现在只需要记住：**你在程序里看到的地址，都是虚拟地址，不是物理地址**。

## 内存的访问过程

### 总线

CPU 通过三条总线与内存通信：

- **地址总线（Address Bus）**：CPU 把要访问的地址发给内存。总线宽度决定寻址范围。
- **数据总线（Data Bus）**：在 CPU 和内存之间传输数据。总线宽度决定每次能传多少位（常见 64 位）。
- **控制总线（Control Bus）**：传输读/写信号、时钟信号等控制信息。

```text
         地址总线（单向，CPU → 内存）
CPU ──────────────────────────────────── 内存
         数据总线（双向）
CPU ──────────────────────────────────── 内存
         控制总线（读/写/使能等信号）
CPU ──────────────────────────────────── 内存
```

### 读操作流程

1. CPU 把目标地址放到地址总线上
2. 设置控制总线为"读"信号
3. 内存控制器解码地址，找到对应的存储单元
4. 内存把数据放到数据总线上
5. CPU 从数据总线读取数据

整个过程需要几个到几十个 CPU 时钟周期（DRAM 访问延迟通常在 50~100 ns，一个 3 GHz CPU 的时钟周期约 0.33 ns，所以一次内存访问大约需要等 150~300 个时钟周期）——这就是为什么 CPU 缓存如此重要，后面第 5 篇会讲。

## 内存中的数据类型

程序里的各种类型，实际上就是对"这些字节该如何解释"的约定：

```text
同样是这 4 个字节：[0x41][0x00][0x00][0x00]

解释为 uint32（小端序）：0x00000041 = 65
解释为 int32（小端序）：0x00000041 = 65
解释为 float32：约 9.1835e-44（符号位=0，指数全0，尾数=0x41）
解释为 4 个 char：'A', '\0', '\0', '\0'（ASCII 65 = 'A'）
```

内存本身不知道自己存的是整数、浮点数还是字符，它只存字节。是程序（编译器生成的机器码）决定怎么解读这些字节。这就是为什么 C 语言的类型强转那么危险——你随时可以告诉 CPU "这块内存是 float，按 float 解读"，即使它实际上存的是整数。

### 常见类型的内存占用

整数类型按位宽分为四级：8 位（1 字节）、16 位（2 字节）、32 位（4 字节）、64 位（8 字节）。Rust 里对应 `i8`/`u8`、`i16`/`u16`、`i32`/`u32`、`i64`/`u64`，大小是语言规范确定的。C 里的 `char` 通常 1 字节，`short` 常见 2 字节，`int` 通常 4 字节，`long long` 8 字节——但 C 标准只保证最小宽度，可移植代码应该用 `int32_t` 这类定宽类型。

浮点数有 32 位的 `float`（Rust 的 `f32`）和 64 位的 `double`（Rust 的 `f64`）两种，分别占 4 字节和 8 字节。

指针櫳手特别说一下：在 64 位系统上，任何指针——无论是 `void*`、`int*` 还是函数指针——都占 8 字节，因为地址就是 64 位的整数。Rust 的 `usize`/`isize` 与平台指针等宽，64 位上同为 8 字节。指针占多少字节，下一篇会详细讨论。

## 内存的组织层次

实际的计算机内存不是铁板一块，而是分层次组织的：

```text
寄存器（Registers）
  └─ 容量：几十个，每个 8 字节
  └─ 延迟：0 周期（CPU 内部）

L1 缓存（Cache）
  └─ 容量：32~64 KiB（每核）
  └─ 延迟：4~5 周期

L2 缓存
  └─ 容量：256 KiB ~ 1 MiB（每核）
  └─ 延迟：10~15 周期

L3 缓存（末级缓存，LLC）
  └─ 容量：4~64 MiB（共享）
  └─ 延迟：30~40 周期

主内存（Main Memory，DRAM）
  └─ 容量：几 GiB ~ 几百 GiB
  └─ 延迟：150~300 周期

存储（SSD / HDD）
  └─ 容量：几百 GiB ~ 几 TiB
  └─ 延迟：数万～数百万周期
```

每向上一层，速度快一个数量级，但容量缩小一个数量级，成本也更高。软件性能优化的很大一部分就是：**让热点数据尽量待在上层**（缓存友好的数据结构、局部性原理）。

## 小结

本篇建立了最基础的物理内存概念：

- 内存由电容（DRAM）或触发器（SRAM）构成，存储比特
- 8 个比特 = 1 字节，字节是最小的可寻址单位
- 每个字节有唯一的地址；多字节数据有大端/小端之分
- CPU 通过地址总线、数据总线、控制总线访问内存
- 程序里的地址是虚拟地址，不是物理地址
- 内存按速度/容量分层：寄存器 → 缓存 → 主内存 → 存储
