## 前言

写了那么久代码，你有没有想过：`int x = 5;` 这一行，那个 `5` 究竟存在哪里？它占了多少空间？CPU 是怎么找到它的？

这个系列从最底层开始讲内存——不是"分配一块内存"这种抽象层面，而是真正搞清楚内存是什么、怎么工作、为什么要这样设计。理解了这些，你看 Rust 的所有权、C 的指针、操作系统的虚拟内存，都会有一种"原来如此"的感觉。

## 内存的物理本质

### 从一个比特开始

计算机里最小的信息单位是**比特（bit）**，它只能存储两种状态：0 或 1。

在实际的 DRAM（动态随机存取存储器，也就是我们通常说的"内存条"）里，每一个比特对应一个**电容**——电容充电表示 1，放电表示 0。电容会缓慢漏电，所以 DRAM 需要周期性刷新（每隔几毫秒就重新充电），这也是它叫"动态"的原因。

相比之下，SRAM（静态随机存取存储器，用于 CPU 缓存）用的是触发器电路，不需要刷新，速度更快，但每个比特需要 4~6 个晶体管，成本和面积都更高。这就是为什么 L1/L2 缓存只有几十 KiB，而内存条动辄十几 GB——SRAM 贵得多、也占地方得多。

### 字节：最小的可寻址单位

8 个比特组成 1 **字节（byte）**。内存以字节为单位编址——每个字节都有一个唯一的**内存地址（address）**，就像门牌号一样。

例如，地址 `0x0000` 处存放字节 `0x65`（十进制 101），`0x0001` 处存放 `0x21`（33），依此类推，每个地址对应独立的 1 字节。

"以字节寻址"是现代计算机的通用设计。CPU 向内存发出一个地址，内存返回那个地址上的 1 个字节（或一次性返回多个连续字节）。

### 多字节数据的存储

`int`（4 字节）、`double`（8 字节）等类型需要占据多个连续字节。这里就产生了一个问题：多字节的数，高位字节放在低地址还是高地址？

这叫**字节序（Endianness）**，有两种：

**大端序（Big-Endian）**：高位字节在低地址，低位字节在高地址。读起来和人写数字的顺序一致。

**小端序（Little-Endian）**：低位字节在低地址，高位字节在高地址。

```
以 32 位整数 0x12345678 为例，存放在地址 0x1000 起：

地址      大端序    小端序
0x1000     0x12      0x78
0x1001     0x34      0x56
0x1002     0x56      0x34
0x1003     0x78      0x12
```

x86/x86-64（也就是你的 PC 和大多数服务器）使用**小端序**。ARM 通常也默认小端序。网络协议（TCP/IP）规定用大端序传输，所以网络编程里经常要做字节序转换（`htonl`、`ntohl`）。

大多数时候你不需要关心字节序，但以下情况必须注意：
- 读写二进制文件（尤其是跨平台时）
- 网络通信
- 直接操作内存（类型转换、联合体等）

## 内存地址空间

### 什么是地址空间

**地址空间**是一组可用的内存地址的集合。在 32 位系统上，地址是 32 位的整数，地址空间大小是 $2^{32}$ = 4 GiB——也就是最多能寻址 4 GB 的内存。在 64 位系统上，地址是 64 位的，理论地址空间是 $2^{64}$ ≈ 16 EiB，实际上目前的 CPU 只用了低 48 位，够用很久了。

32 位地址空间从 `0x00000000` 到 `0xFFFFFFFF`，共 4,294,967,296 个字节（4 GiB）。

### 物理地址 vs 逻辑地址

这里有个关键区分：

- **物理地址（Physical Address）**：内存条上真实的位置编号，由内存控制器直接使用。
- **逻辑地址 / 虚拟地址（Virtual Address）**：程序代码里使用的地址，由操作系统和 CPU 的 MMU（内存管理单元）负责翻译成物理地址。

这个虚拟地址的设计是操作系统最重要的机制之一，我们放到第 4 篇详细讲。现在只需要记住：**你在程序里看到的地址，都是虚拟地址，不是物理地址**。

## 内存的访问过程

### 总线

CPU 通过三条总线与内存通信：

- **地址总线（Address Bus）**：CPU 把要访问的地址发给内存。总线宽度决定寻址范围。
- **数据总线（Data Bus）**：在 CPU 和内存之间传输数据。总线宽度决定每次能传多少位（常见 64 位）。
- **控制总线（Control Bus）**：传输读/写信号、时钟信号等控制信息。


### 读操作流程

1. CPU 把目标地址放到地址总线上
2. 设置控制总线为"读"信号
3. 内存控制器解码地址，找到对应的存储单元
4. 内存把数据放到数据总线上
5. CPU 从数据总线读取数据

整个过程需要几个到几十个 CPU 时钟周期（DRAM 访问延迟通常在 50~100 ns，一个 3 GHz CPU 的时钟周期约 0.33 ns，所以一次内存访问大约需要等 150~300 个时钟周期）——这就是为什么 CPU 缓存如此重要，后面第 5 篇会讲。

## 内存中的数据类型

程序里的各种类型，实际上就是对"这些字节该如何解释"的约定：

```
同样是这 4 个字节：[0x41][0x00][0x00][0x00]

解释为 uint32（小端序）：0x00000041 = 65
解释为 int32（小端序）：0x00000041 = 65
解释为 float32：约 9.1835e-44（符号位=0，指数全0，尾数=0x41）
解释为 4 个 char：'A', '\0', '\0', '\0'（ASCII 65 = 'A'）
```

内存本身不知道自己存的是整数、浮点数还是字符，它只存字节。是程序（编译器生成的机器码）决定怎么解读这些字节。这就是为什么 C 语言的类型强转那么危险——你随时可以告诉 CPU "这块内存是 float，按 float 解读"，即使它实际上存的是整数。

### 常见类型的内存占用

整数类型按位宽分为四级：8 位（1 字节）、16 位（2 字节）、32 位（4 字节）、64 位（8 字节）。Rust 里对应 `i8`/`u8`、`i16`/`u16`、`i32`/`u32`、`i64`/`u64`，大小是语言规范确定的。C 里的 `char` 通常 1 字节，`short` 常见 2 字节，`int` 通常 4 字节，`long long` 8 字节——但 C 标准只保证最小宽度，可移植代码应该用 `int32_t` 这类定宽类型。

浮点数有 32 位的 `float`（Rust 的 `f32`）和 64 位的 `double`（Rust 的 `f64`）两种，分别占 4 字节和 8 字节。

指针单独说一下：在 64 位系统上，任何指针——无论是 `void*`、`int*` 还是函数指针——都占 8 字节，因为地址就是 64 位的整数。Rust 的 `usize`/`isize` 与平台指针等宽，64 位上同为 8 字节。指针的本质和运算，下一篇会详细讨论。

## 内存中的值与运算

### 整数的二进制表示

内存里存的是字节，字节里存的是比特，比特只有 0 和 1。那一个普通的整数 `13` 是怎么表示的？

以 8 位无符号整数为例，每一位的权重从右到左是 $2^0$、$2^1$、$2^2$……$2^7$：

```
位    7   6   5   4   3   2   1   0
值    0   0   0   0   1   1   0   1
权   128  64  32  16   8   4   2   1

0×128 + 0×64 + 0×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1 = 13
```

8 位无符号整数（`uint8_t` / Rust 的 `u8`）能表示 0~255（即 $2^8 - 1$）。32 位无符号整数能表示 0~4,294,967,295（即 $2^{32} - 1$）。

### 十六进制：写地址的通用语

代码里经常看到 `0x1A2B`、`0xFF`、`0x00400000` 这样的写法，这是**十六进制（Hexadecimal，简称 hex）**，基数是 16。

十六进制用 0~9 和 A~F 表示 16 个数字，其中 A=10、B=11、C=12、D=13、E=14、F=15。

**为什么用十六进制？** 因为 4 个二进制位（一个半字节，nibble）恰好对应 1 位十六进制，8 个二进制位对应 2 位十六进制。写二进制太长，写十进制和位操作没有直观联系，十六进制是最合适的折中：

```
二进制       十六进制   十进制
0000         0          0
0101         5          5
1010         A          10
1111         F          15
1011 0110    B6         182
1111 1111    FF         255
```

**十六进制转十进制**：每一位的权重是 $16^0$、$16^1$、$16^2$……

```
0x1A2B = 1×16³ + A×16² + 2×16¹ + B×16⁰
       = 1×4096 + 10×256 + 2×16 + 11×1
       = 4096 + 2560 + 32 + 11
       = 6699
```

**十六进制加法**：逢 16 进一，和十进制逢 10 进一完全对称：

```
  0x9E
+ 0x47
──────
  个位：E + 7 = 14 + 7 = 21 = 16 + 5 → 写 5，进 1
  十六位：9 + 4 + 1（进位）= 14 = E
  结果：0xE5
```

验证：$0x9E = 158$，$0x47 = 71$，$158 + 71 = 229 = 0xE5$。✓

内存地址通常用十六进制表示，因为两位 hex 恰好是 1 个字节，读起来非常直观：`0x0000_7FFF_FFFF_F000` 这个地址光看结构就知道是 48 位有效位、页对齐（末尾三个零 = 4096 字节对齐）。

### 负数：补码

有符号整数用**二进制补码（Two's Complement）**表示负数。规则是：正数保持原样；负数先按位取反，再加 1。

以 8 位有符号整数表示 `-13`：

```
第一步：13 的二进制      00001101
第二步：按位取反（反码）  11110010
第三步：加 1（补码）     11110011  ← 这就是 -13 在内存里的样子
```

验证：`11110011` 最高位是 1（负数标志）。还原：取反得 `00001100`，加 1 得 `00001101` = 13，所以它是 -13。✓

补码的妙处在于：加法电路不需要区分正负，直接按二进制相加，借位自然溢出就能得到正确结果：

```
  3 + (-3) = ?

  00000011   (+3)
+ 11111101   (-3 的补码)
───────────
 100000000   ← 最高位进位溢出，8 位截断后 = 00000000 = 0  ✓
```

8 位有符号整数的范围是 -128~127。最小值 -128 没有对应的正数（因为 128 超出了表示范围），所以有符号整数的最小值总比最大值的绝对值多 1。

### 整数溢出

当运算结果超出类型的表示范围，就会发生**整数溢出**：

```
u8 最大值 255 再加 1：
  11111111 + 00000001 = 100000000 → 截断为 00000000 = 0（回绕）
```

C/C++ 中无符号整数溢出是良定义行为（回绕），有符号整数溢出是**未定义行为**——编译器可以假设它不会发生，进而做出激进优化，导致难以复现的 bug。Rust 在 debug 模式下溢出会 panic，release 模式下回绕；需要回绕时应显式调用 `.wrapping_add()` 等方法。

### CPU 如何对内存中的值做运算

CPU 不直接"在内存里"做运算——它先把值**加载（load）到寄存器**，在寄存器里完成计算，再把结果**存回（store）内存**：

```nasm
; c = a + b; 对应的机器指令（x86-64 概念）
mov eax, [addr_a]   ; 从内存加载 a 的值到寄存器 eax
add eax, [addr_b]   ; eax = eax + b（从内存读 b，在寄存器内相加）
mov [addr_c], eax   ; 把寄存器里的结果存回内存（c 的地址）
```

寄存器是 CPU 内部的存储单元，访问延迟为 0。所有算术逻辑运算（加减乘除、位运算、比较）都在寄存器中完成。内存是数据的"家"，寄存器是数据的"工作台"。

### 位运算

位运算直接作用于整数的二进制表示，是底层编程不可或缺的工具：

- `AND`（`&`）：`00001111 & 11110000 = 00000000`，清除/取特定位
- `OR`（`|`）：`00001111 | 11110000 = 11111111`，设置特定位
- `XOR`（`^`）：`00001111 ^ 11111111 = 11110000`，翻转特定位
- `NOT`（`~`）：`~00001111 = 11110000`，全部翻转
- 左移（`<<`）：`00000001 << 3 = 00001000`，等效 ×$2^3$
- 右移（`>>`）：`00010000 >> 2 = 00000100`，等效 ÷$2^2$

左移 1 位等于乘 2，右移 1 位等于整除 2。编译器经常用移位代替乘除法，因为移位指令只需 1 个时钟周期，整数乘法需要 3~5 个，除法则需要 20~90 个。

用位运算解析一个字节的高低半字节（常见于网络协议头、像素格式）：

```c
uint8_t byte = 0xB6;         // 10110110
uint8_t low4  = byte & 0x0F; // 00000110 = 6，掩码 AND 取低 4 位
uint8_t high4 = byte >> 4;   // 00001011 = 11，右移 4 位取高 4 位
```

## 内存的组织层次

实际的计算机内存不是铁板一块，而是分层次组织的：

- **寄存器**：几十个，每个 8 字节；延迟 0 周期（CPU 内部）
- **L1 缓存**：32~64 KiB（每核）；延迟 4~5 周期
- **L2 缓存**：256 KiB ~ 1 MiB（每核）；延迟 10~15 周期
- **L3 缓存（LLC）**：4~64 MiB（共享）；延迟 30~40 周期
- **主内存（DRAM）**：几 GiB ~ 几百 GiB；延迟 150~300 周期
- **存储（SSD / HDD）**：几百 GiB ~ 几 TiB；延迟数万～数百万周期

每向上一层，速度快一个数量级，但容量缩小一个数量级，成本也更高。软件性能优化的很大一部分就是：**让热点数据尽量待在上层**（缓存友好的数据结构、局部性原理）。

## 小结

本篇建立了最基础的物理内存概念：

- 内存由电容（DRAM）或触发器（SRAM）构成，存储比特；字节是最小的可寻址单位
- 每个字节有唯一的地址；多字节数据存在大端/小端之分
- 整数用二进制表示，负数用补码；溢出时 C 有符号整数是未定义行为，Rust 会 panic
- CPU 把内存中的值加载到寄存器运算，再存回内存；位运算直接操作二进制位
- CPU 通过地址总线、数据总线、控制总线访问内存
- 程序里看到的地址都是虚拟地址，不是物理地址
- 内存按速度/容量分层：寄存器 → 缓存 → 主内存 → 存储
